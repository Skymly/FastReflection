# FastReflection 1.0 quality gates

The authoritative spec for the build and CI gates every 1.0 PR is verified under. Decided by the wayfinder council on map [#1](https://github.com/Skymly/FastReflection/issues/1); specified on [#21](https://github.com/Skymly/FastReflection/issues/21). The gate list itself was fixed by the council — "quality-gate engineering needs no decision" — so this document spells the buildable form; the numbers below (90% line coverage, 25% regression tolerance, linux-x64-only smoke, `--job short`) are spec-hop spellings of that decision, adjustable by maintainer override without reopening the spec.

The contracts these gates encode are already decided: the AOT/trim annotation set is [#9](https://github.com/Skymly/FastReflection/issues/9) as spelled in [the public-API spec](1.0-public-api.md), the two-runner matrix and TFM policies are [#19](https://github.com/Skymly/FastReflection/issues/19), and the XML-documentation rule is [#8](https://github.com/Skymly/FastReflection/issues/8)'s documentation contract. Gates land on the current three-TFM surface now; `#if` baselines and leg lists follow whatever the shipped set is, so the net10.0 legs, the satellite baselines, and the extra smoke scenarios arrive inside #20's own PRs — inheriting the gates through shared props rather than retro-fitting them.

## Analyzer and warning gates

Shared props apply to every *shipped* project — the core today, the two satellites when #20 lands them. Tests, benchmarks, the smoke app and the build project keep warnings, not errors.

- `IsAotCompatible=true` on every shipped project, so the trim, AOT and single-file analyzers fire at build time instead of at a consumer's publish; IL2xxx/IL3xxx diagnostics become errors under warnings-as-errors, making the #9 annotation contract un-regressible.
- `AnalysisLevel=latest` for the SDK NetAnalyzers.
- `TreatWarningsAsErrors=true` on shipped projects only.
- `Microsoft.CodeAnalysis.PublicApiAnalyzers` with `PublicAPI.Shipped.txt`/`PublicAPI.Unshipped.txt` per package, so the frozen 1.0 surface is diffable in review and unshipped-surface drift fails the build. The net8+-only surface (the span invokers) rides in a per-TFM file instance (`PublicAPI/<tfm>/PublicAPI.*.txt`) — the analyzer's verified conditional-API mechanism is multiple file instances, not in-file `#if` directives.
- `Microsoft.DotNet.PackageValidation` with `EnablePackageValidation=true`, running intra-package asset-compatibility checks only — no baseline exists at 1.0. Intentional per-TFM differences (the `#if`-gated span invokers) are recorded in the suppression file with reasons. `PackageValidationBaselineVersion` is a post-1.0 follow-up after the first publish.

### NoWarn inventory

Every suppression is explicit and commented:

- The shipped `1591` suppression (`src/FastReflection/FastReflection.csproj`) is removed — XML documentation becomes required on public members, `<exception>` included per #8's documentation rule. The implementing PR lands the missing doc comments the un-suppression makes necessary.
- NETSDK1138 is suppressed only `Condition="'$(TargetFramework)' == 'net8.0'"` once that leg is past EOL, with a comment citing #19's "drops only at a major" policy — the EOL stance is visible rather than global silence.
- Any further suppression needs an inline justification.

## SDK pin

`global.json` pins the `10.0.x` SDK band with `rollForward: latestFeature`, so the net10.0 legs build identically locally and in CI once they exist; both runner images carry the band post-GA.

## CI topology

A Nuke `GitHubActions` attribute change, then `ci.yml` is regenerated — never hand-edited. `publish.yml` is untouched.

- **windows-latest**: builds all target frameworks; tests `net472;net6.0;net8.0;net10.0` — the legs that exist (`net472;net6.0;net8.0` today; net10.0 arrives with #20's topology).
- **ubuntu-latest**: builds all target frameworks (net462 compiles via the already-referenced `Microsoft.NETFramework.ReferenceAssemblies`); tests the non-.NET-Framework legs `net6.0;net8.0;net10.0`; runs the linux-x64 AOT smoke.
- The `Test` target selects its framework legs by OS — net472 only on Windows — rather than forking the test project.

## AOT smoke — `tests/FastReflection.AotSmoke`

A console test app asserting the #9 contract end-to-end through a real `PublishAot` binary, so the fallback contract is proven, not inferred from analyzers.

- Multi-targeted `net8.0;net10.0` (net8.0 alone until the net10.0 leg exists); published `PublishAot` for `linux-x64` on the ubuntu leg — the only RID at 1.0 — then executed. Exit code 0 on pass; nonzero names the failed scenario.
- Fixed scenarios per #9: `Unreflect` exact bind completes; a type accessor over a rooted type (members kept by `DynamicallyAccessedMembers`) reads and writes; reflection fallbacks complete (getter / invoker / factory paths, including the span invoker's `MethodInvoker` fallback); the adapted `Ref<T>` typed invoker throws `NotSupportedException`.
- The contract grows with the surface: as #20 lands, add a bound call completing through reflection completion and one scenario per satellite.
- The app asserts external behavior only — exit code plus contract scenarios — never internals.

## Coverage gate

- `coverlet.collector` on the test project; `dotnet test --collect:"XPlat Code Coverage"` producing cobertura on the newest modern leg — net10.0 once #20's topology lands, net8.0 until then. One leg only, so no cross-leg merge tooling (ReportGenerator) is expected; verify at implementation.
- The gate fails below **90% line coverage on any shipped assembly**.
- The report uploads as a CI artifact so a reviewer can see what a diff leaves uncovered.

## Benchmark gate

- The BenchmarkDotNet suite keeps today's BCL-baseline rows and gains reference-library comparison rows *as the corresponding features land*: fast-member accessor get/set and `ObjectReader` feed; Dynamitey invoke/get/set by name and convert; DotNext `Unreflect`/invoker shapes; Namotion XML-docs reads.
- Benchmark legs `net472;net8.0;net10.0` — the legs that exist (`net472;net8.0` today; net10.0 arrives with #20's topology).
- A dedicated Nuke `Benchmark` target plus a windows-latest CI job runs on PRs and main with the repo's `--job short` convention; every run uploads its artifacts.
- **Gate math**: a FastReflection benchmark fails the job when its mean is >25% slower than the committed baseline file under `benchmarks/` — the tolerance covers hosted-runner jitter. Reference-library rows are reported, never gated; no absolute budgets.
- Baseline refresh is a deliberate maintainer run plus PR — improvement or accepted regression is an explicit act, never silent drift.

## Gate audit

One-time, part of this spec's implementation and recorded in the implementing PR: prove each gate fails when violated — a deleted `PublicAPI` entry, an undocumented public member, a broken annotation, a doctored smoke scenario, a synthetic coverage drop, an inflated baseline mean — and passes on compliance. The audit checklist is this spec's test suite; product-code seams stay unchanged (the public surface and the `ForceReflectionFallback` parity leg; the smoke app adds no internal seam).

Modules verified: every shipped project's analyzer/baseline/validation state; the generated `ci.yml` legs on both runners; the AOT smoke binary's real publish + run; the coverage collection and threshold; the benchmark comparison math against the baseline file.

Prior art: the `Test`/`Pack`/`Publish` Nuke targets and attribute-generated workflows in `build/`; `FallbackTests` as the fallback-path precedent; `MemberAccessBenchmarks` conventions (`MemoryDiagnoser`, `Baseline = true`) for new comparison rows.

## Out of scope

- The feature work itself (#20) and the scope-ADR / `docs/plans/1.0.md` / non-goal-rewrite hop (#22) — this spec constrains those PRs, it does not implement them.
- Any annotation *content* — the `RequiresDynamicCode`/`DynamicallyAccessedMembers` contract is #20's; this spec only makes violations un-mergeable.
- win-x64 or macOS AOT smoke RIDs, mutation testing, style-rule enforcement (`EnforceCodeStyleInBuild` / `.editorconfig` rulesets), package-validation baseline versions (post-1.0 publish), and benchmark *absolute* budgets — regression is gated relative to baseline, never to a wall-clock promise.
- Release mechanics: no tag, Release, or NuGet push; `publish.yml` unchanged; `<Version>` stays `0.1.0`.

## Implementation notes

- Suggested PR slicing (one PR per unit, sequenced ahead of the feature PRs): (1) `global.json` + shared gate props — `IsAotCompatible`, `AnalysisLevel`, `TreatWarningsAsErrors`, the NoWarn inventory, PublicApiAnalyzers with the 0.1-surface baselines, PackageValidation — plus the XML doc comments the 1591 un-suppression requires; (2) two-runner CI — Nuke attribute change, regenerated `ci.yml`, OS-conditional `Test` legs; (3) `FastReflection.AotSmoke` + linux-x64 publish/run leg; (4) coverage collection + 90% gate + artifact upload; (5) benchmark comparison rows + baseline file + `Benchmark` target/job + regression math. Each PR records its gate-audit evidence.
- Verify at implementation, don't assume: `PublicAPI` `#if` support per-TFM on the pinned analyzer version; the ubuntu image's .NET 10 SDK presence; whether coverlet merging across legs needs ReportGenerator (the spec gates one leg, so likely not).
- `docs/release/1.0-acceptance.md` will cite the green runs, the coverage artifact, and the benchmark report produced here — the acceptance doc itself is a separate hop.
- Traceability: four-part AOT gate #9; two-runner matrix, baseline columns, NETSDK1138 handling #19; XML-doc contract #8; cache/strong-key constraints behind the annotation suppressions #4/#6; the gated surface #20.
